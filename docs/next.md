# 接下來要做的

已經決定要做、但還沒做的事。寫在這裡是為了換機器、隔一段時間回來時接得回去——
知道「為什麼要做」跟知道「要改哪幾個檔案」一樣重要,所以兩邊都寫。

做完一項就從這裡刪掉,並在 [CHANGELOG.md](../CHANGELOG.md) 留下紀錄。

## 換機器之後先確認環境還是好的

```bash
npm ci
npm run typecheck   # 型別
npm test            # 單元測試
npm run e2e         # 端對端
npm run harness:ui  # 真的 Electron app 跑一遍介面情境,會留截圖
```

`npm run harness:ui` 是最慢但最重要的一道:單元測試在純 node 底下跑,看不到 app 裡
`process.execPath` 是 Electron 這件事。評測的實驗 5 第一次 48 跑就是被這一類差異作廢的。

## 1. 實驗:先獨立作答,再公開互相攻擊(Sequential vs Independent-first)

**還沒開跑,而且要先取得使用者同意**(比照實驗 4 的規矩)。下面是預先登記的草稿,
開跑前要補上次數與確切的 commit,而且**不可以先看結果再回頭改這一段**。

### 背景

預設討論仍是「依序輪流,每人看得到之前所有人的話」,目前已可選「獨立首輪後互評」。
實驗 3 的事後觀察已經看到它的影子:圓桌沒有全對的 10 次裡,**8 次結果卡寫著「✓ 審查通過」**,
也就是審查者照著執行者的說法複誦。產品後來把交叉審查改成乾淨 context 就是為了切斷這條路,
這次則已補上討論階段的 context 隔離;**效果尚未量過**。

文獻同向:同質 agent 擴張有強烈遞減報酬,而且強模型彼此錯得更像
([arXiv 2602.03794](https://arxiv.org/html/2602.03794v1));算力對齊後 multi-agent debate
普遍打不贏單 agent baseline([arXiv 2502.08788](https://arxiv.org/abs/2502.08788))。

### 假設

- **H1**:Independent-first 的測試通過率高於 Sequential。
- **H2**(比較有意思的那個):Independent-first 的**錯誤相關性**低於 Sequential。

### 條件

- **A(Sequential)**:現況。A 答 → B 看 A → C 看 A+B → …
- **B(Independent-first)**:每位成員各自在乾淨 context 下答一次,全部答完才公開,
  然後才進入互相挑錯與驗證。

### 指標

- 主指標:錯誤相關性。四位成員獨立答錯**不同**的東西 vs 答錯**同一個**東西。
  具體定義要在開跑前寫死——建議用「同一題上,任兩位成員的失敗測試集合的 Jaccard 相似度」,
  平均起來當一個數。這個指標才是直接回答「共享多少思考會讓集體錯誤同步化」的那一個。
- 次指標:測試通過率、全對率、時間、token。

### 工程已備妥,開跑前還要決定

討論設定、陣容、多條件 runner、隔離候選證據、失敗測試 ID 與 Jaccard 已完成;
操作與限制見 [評測文件](../eval/README.md#多條件與預算)。新正式實驗仍未執行。

1. 先取得使用者同意,決定模型、題組、每組次數、候選數與公開驗證指令。
2. 要量產品文字討論模式,比較 `roundtable` / `independent-first`;兩邊設定相同回合上限。
   要量每人的程式錯誤集合,比較 `sequential-candidates` / `independent-candidates`:
   各候選在全新 app 與原始目錄作答,循序組取得先前候選檔案,之後兩邊用相同整合流程。
   **這是不同操作化定義,不能把候選實驗當成產品文字討論的直接成效。**
3. 固定 Jaccard 規則:兩份失敗集合皆空時不進平均、另列全對配對;app 未完成另列未知。
   同一任務內先平均配對,以完整任務為統計單位,不能把每個配對當獨立樣本。
4. 題組仍需校準;優先考慮 `forth-fix`、`poker-fix`,基本題有天花板問題。
5. 用 `--dry-run` 保存設定與 protocol,在 [EXPERIMENTS.md](../eval/EXPERIMENTS.md)
   填入確切乾淨 commit、次數、主要對照與判斷標準,才加 `--approve-experiment` 開跑。

## 2. 校準算力對齊的 baseline

`solo-budget` 的多候選與公開棘輪選擇已完成。仍需經同意的獨立校準來固定 token 目標、
最大嘗試次數、允許偏差與有意義的公開關卡,不可以拿正式結果回頭調 N。
只有語法檢查時,等分會保留任務起點,不能用隱藏分數偷挑候選。

token 目標是完成一次候選後檢查,可能超出一個候選的用量;達次數上限但未達目標、
或任何回合缺用量,都不能宣稱已對齊。正式比較必須報實際總量與偏差,異質模型 token
也不是等價 FLOPs。這些限制與准入標準要在開跑前寫入實驗紀錄。
