## 空狀態

搜尋或分段過濾後 0 筆時,取代卡片列表:

- 主句:**沒有符合的範本**
- 次句:**試試清空搜尋,或改選「全部」。**

## 分組與排序

- 「現成範本」在上、「從空白開始」在下。空白是找不到現成項時的退路,不要置頂。
- 空白組只收 `blank-cli.json` / `blank-api.json`(或 `id` 為 `my-cli` / `my-api`)。Aider 不是空白範本,放「現成範本」,且只在「全部」可見。

## 刻意不改

- 對話框標題維持 **新增 CLI / API**
- 範本 JSON 的 `label` / `description`(含「我的 CLI」「我的 API」)維持不變
- 關閉按鈕 ✕、編輯器其餘文案不在此規格範圍

## 附件錯誤(不靜默丟檔)

`#attach-error` 設 `role="alert"`,錯誤留到下次附加／移除／送出才清,不自動消失。一次只顯示第一個錯誤。句式統一為 **無法附加「{檔名}」:{原因}**,不可只寫「附加失敗」。上限數字以後端 `limits` 為準,預設如下:

| 情況 | 用字 |
| --- | --- |
| 超過 10 檔 | **無法附加「{檔名}」:一次最多 10 個檔案** |
| 單檔超過 20 MB | **無法附加「{檔名}」:單檔不能超過 20.0 MB** |
| 合計超過 50 MB | **無法附加「{檔名}」:這次附件合計不能超過 50.0 MB** |
| 副檔名不符 | **無法附加「{檔名}」:不支援此類型,請改傳圖片、文字檔或 PDF** |
| 內容與副檔名不符 | **無法附加「{檔名}」:內容不是 PNG 格式(副檔名與實際內容不符)**(副檔名隨檔而變;後端 magic bytes 訊息會帶上檔名) |

沒有檔名的例外(例如對話框本身失敗)才用 **無法附加檔案:{原因}**。

白名單副檔名:png / jpg / jpeg / webp / gif / txt / md / json / csv / log / pdf。有附件 IPC 時,驗證與儲存都在 main process;renderer 負責選檔、拖放,並把後端 `{ name, error }` 編成上表句式。

## 任務結果卡

分工任務結束時(總結之後)出現,一次看完誰做完了、審查結論、這次任務改了哪些檔案、花了多少時間與 token。刻意和對話泡泡不同:上方一條「任務結束」分隔線、置中、沒有頭像,標題是一整條品牌藍的色帶。主色是品牌藍;只有需要留意或有人失敗時,狀態標籤換成警示色。成員各自的結論徽章與增刪比例條維持語意色。只給人看,不送進成員的提示詞;純文字版存在訊息的 text,匯出與歷史紀錄用。

| 位置 | 用字 | 備註 |
| --- | --- | --- |
| 分隔線 | **任務結束** | 品牌藍,不吸頂 |
| 標題 | **◎ 任務結果** | |
| 狀態標籤 | **全部審查通過** / **已依審查意見修復** / **有 {n} 位需要留意** / **有 {n} 位執行失敗** | 最嚴重的那個說了算;後兩者用警示色 |
| 數字標籤 | **⏱ {m} 分 {s} 秒**、**◇ {輸入} / {輸出} token**、**$ {費用}** | 沒有回報用量就不顯示 token |
| 用量不完整 | **有 {n} 個回合沒有回報用量,實際用量更多** | warn 色 |
| 成員結論 | **✓ 審查通過** / **已修復(未再審查)** / **⚠ 有未解決的問題** / **尚未審查** / **✗ 執行失敗** | 和流程實際的走向同一個判斷。修復後由原本的審查者複查:複查通過才是「審查通過」,複查仍有問題是「有未解決的問題」;只有複查本身沒跑成時才是「已修復(未再審查)」,用中性色。執行中途失敗、但改了檔案而照樣送審的成員,結論依審查而定 |
| 審查者 | **{名稱} 審查** | |
| 檔案區標題 | **改動 {n} 個檔案** / **這次任務沒有改動檔案** | 只算這次任務(任務開始前後比對),不含使用者之前的改動 |
| 檔案列 | 狀態膠囊 + 路徑 + **+{增} −{刪}** + 5 格比例條 | 最多 12 個,之後 **還有 {n} 個**;點一下跳到「檔案改動」的那個檔案 |
| 連結 | **開啟檔案改動 →** | |

## 檔案改動(工作目錄不是 git repo)

預設工作區不是 git repo。不是 git repo 時,任務開始前記下工作目錄裡小型文字檔的內容(單檔 256 KB、總共 20 MB 以內,只放記憶體),「檔案改動」拿現在的檔案比對。比對的基準是「最近一次任務開始前」,不是上一次 commit,摘要列要講明。

| 位置 | 用字 | 備註 |
| --- | --- | --- |
| 摘要列後段 | **不是 Git 版本庫:列出 {時間} 開始的最近一次任務以來的改動** | 時間只到分鐘 |
| 還沒有任務可比對 | **這個工作目錄不是 Git 版本庫。執行一次分工任務之後,這裡會列出那次任務開始以來的改動;在資料夾執行 git init,則會改成相對上一次 commit 比對。** | |
| 沒有保存原始內容 | **任務開始前沒有保存這個檔案的內容(超過單檔 256 KB 或總共 20 MB 的上限),無法逐行比對** | 照樣列出檔名與狀態 |
| 檔案現在太大 | **這個檔案超過 256 KB,不逐行比對** | 例如新增的大檔 |
| 改動的檔案太多 | **改動的檔案太多,這個檔案沒有逐行比對** | 比對時間超過 1.5 秒之後的檔案;每比完一個檔案就讓出主程序,畫面不會卡 |

## 每回合逾時上限(擴充編輯器)

內建的 Claude Code 與 Codex 不開放調整(預設 20 分鐘);API 與自訂 CLI 擴充可以在擴充編輯器設定,對應 JSON 的 `timeoutMs`。逾時的錯誤訊息只在擴充上提示怎麼延長,不叫內建 CLI 的使用者去改一個不存在的設定。

| 位置 | 用字 | 備註 |
| --- | --- | --- |
| 欄位名 | **每回合逾時上限** + 小字 **分鐘** | 基本設定分頁,模型欄位下方;CLI 與 API 都顯示 |
| placeholder | **預設 20** | 留空就不寫 `timeoutMs` |
| 說明 | **成員一回合最多跑多久。本機大模型第一次載入、或任務很大時可能需要更久;留空就是預設的 20 分鐘。** | |
| 逾時錯誤的後半句 | **如果這個模型需要更久,可以在「設定 → CLI 與擴充」編輯這個擴充,調高「每回合逾時上限」。** | 只有 API 與自訂 CLI 擴充 |

## 分工原文

主持人的分工輸出(多半是一串 JSON)成功解析後,下方已經有「分工結果」卡片,原文只是重複又難讀。由主程序在訊息上標 `rawPlan`,介面收起原文;解析失敗時不標,原文完整顯示,讓人看得出哪裡不對。

| 位置 | 用字 | 備註 |
| --- | --- | --- |
| 說明 | **分工已整理在下方的「分工結果」。** | 取代原文 |
| 展開 | **查看主持人的原始輸出** | `<details>`,預設收起 |

## 交叉審查的結論與依據

審查訊息的標題列加上結論徽章,內容上方加一行「審查者看了什麼」。修復後的複查多一個品牌藍的 **複查** 徽章(英文 **re-check**),滑過說明「修復之後的第二次審查:確認問題修好了,也沒有弄壞別的地方」。結論由主程序寫進訊息(`message.review.verdict`),與決定要不要進修復回合是同一個判斷,介面不自己從文字猜。`[NO_ISSUES]` 是給程式看的標記,審查訊息裡不顯示。

| 位置 | 用字 | 備註 |
| --- | --- | --- |
| 結論徽章:通過 | **✓ 審查通過** | ok 色;提示:**審查者明確表示沒有問題** |
| 結論徽章:有意見 | **⚠ 提出問題** | warn 色;提示:**審查者沒有宣告沒問題:意見會交給被審者修復,或帶進總結**。不寫「需要修正」,沒有改檔權限的成員是帶進總結 |
| 結論徽章:失敗 | **✗ 審查未完成** | danger 色;提示:**審查出錯或沒有回覆,這份工作不算審查過** |
| 依據列開頭 | **審查「{名稱}」** | 後面以 ` · ` 接下列其中一項 |
| 自己開檔案的審查者 | **自己打開檔案檢查** | CLI 成員 |
| 附上內容、可自己讀檔 | **附上 {n} 個檔案的內容,也能自己讀檔** | API 範本開了檔案工具 |
| 只看附上的內容 | **附上 {n} 個檔案的內容** | |
| 超過附內容上限 | **另有 {n} 個沒附上內容** | 對應的檔名改用虛線框;提示:**這個檔案超過上限,沒有附上內容;點一下在「檔案改動」中查看** |
| 讀不到內容 | **{n} 個讀不到** | 已刪除、不是文字檔或沙箱拒絕;檔名同樣虛線框,提示:**審查者讀不到這個檔案(已刪除、不是文字檔或被拒絕);點一下在「檔案改動」中查看** |
| 沒有改動 | **工作目錄裡沒有偵測到檔案改動** | 只談工作目錄,工作目錄以外不在範圍內 |
| API 成員沒改檔 | **依工具紀錄,「{名稱}」沒有改檔** | |
| 看不到改動 | **⚠ 看不到實際改動,只能依回報判斷** | warn 色 |
| 沒有改檔權限 | **「{名稱}」沒有改檔權限,只審回報** | |
| 檔名(可點) | 等寬字型膠囊,最多 6 個,之後 **還有 {n} 個** | 點檔名打開「檔案改動」並展開、捲到那個檔案;提示:**在「檔案改動」中查看** |
| 點的檔案不在改動清單 | **「{檔名}」不在這份改動清單裡:可能被 .gitignore 忽略,或超過顯示上限。** | 顯示在「檔案改動」視窗最上方。審查的清單看工作目錄;git repo 的改動視窗看 git,兩者範圍不同 |
