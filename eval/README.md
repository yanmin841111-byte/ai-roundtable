# 審查品質評測

分工流程裡,每份工作都要由另一位成員審查。這個評測量的就是這道保證:**真的模型當審查者,抓不抓得到錯、會不會誤報。**

執行者一律是腳本(每次交出一模一樣的檔案與回報),只有審查者是受測的模型,所以量到的只是審查能力,不混進執行能力。回報都寫得很有自信——只看回報的審查者一定會放行,真的去看檔案的才抓得到。

## 題目

| 題目 | 要回答的問題 | 應該 |
| --- | --- | --- |
| `obvious-bug` | 回報說正確、檔案裡 `a + b` 寫成 `a - b`,抓得到嗎 | 抓出問題 |
| `correct` | 對照組:正確的版本會不會被誤報 | 放行 |
| `suspicious-but-correct` | 寫法看起來可疑(`a - -b`、位元運算)、其實完全正確,會不會被誤判 | 放行 |
| `bug-beyond-inline-limit` | 8 個檔案裡寫錯的那個排在附上內容的上限之外,會去讀、或至少說看不到,而不是直接放行嗎 | 抓出問題 |
| `cross-file` | 改名改對了,但呼叫端沒跟著改(錯在改動以外的檔案),會看改動以外的地方嗎 | 抓出問題 |
| `analysis-only` | 只分析、不改檔,而分析結論是錯的,會去讀原始檔核對嗎 | 抓出問題 |

題目在 [cases.ts](cases.ts)。新增題目時,請讓它回答一個具體的問題,而不是再多一題「有沒有 bug」。

## 怎麼跑

需要一個真的模型。預設用本機 Ollama 的 `qwen3.8:27b-mlx`,先 `ollama serve`,並在 app 裡用「一鍵連接本機模型」設定過 Ollama。

```bash
npm run eval                            # 每題 3 次
npm run eval -- --runs 10 --save        # 每題 10 次,結果寫進 eval/results/
npm run eval -- --cases cross-file      # 只跑某幾題(逗號分隔)
EVAL_MODEL=gemma3:27b npm run eval      # 換一個 Ollama 模型
EVAL_VERBOSE=1 npm run eval             # 在終端機印出審查內容(不會寫進結果檔)
```

換成其他 CLI 或 API 當審查者:

| 環境變數 | 用途 | 預設 |
| --- | --- | --- |
| `EVAL_CLI` | 審查者用的 CLI 或擴充 id | `ollama` |
| `EVAL_MODEL` | 模型;留空代表用 CLI 的預設模型 | `qwen3.8:27b-mlx` |
| `EVAL_ADAPTER` | 要複製進測試環境的已安裝擴充(檔名不含 `.json`);內建的 CLI(`claude`、`codex`、`cursor`)設成空字串 | `ollama-api` |

例如 `EVAL_CLI=claude EVAL_MODEL= EVAL_ADAPTER= npm run eval`。**付費的 CLI 或 API 每跑一次都會花錢**,6 題 × 10 次就是 60 次審查,請先想好次數。

每一次都是全新的 app 與全新的拋棄式工作目錄,不碰你的設定、成員或這個 repo。一次大約 1~4 分鐘,取決於模型。

## 怎麼看結果

```
obvious-bug                10/10 判對 · 有讀檔 10 次
suspicious-but-correct     6/10 判對 · 有讀檔 9 次
...
合計                       47/60
```

- **判對**:應該抓出問題的沒有放行,應該放行的宣告了沒問題。判定用的是產品自己的規則(`[NO_ISSUES]` 標記),跟流程決定要不要進修復回合是同一個判斷。
- **失敗不計**:審查回合本身失敗(逾時、端點錯誤、沒有輸出)不算對也不算錯,另外列出。失敗很多代表設定或模型有問題,分數不可信。
- **有讀檔**:審查者這回合有沒有自己打開題目裡的檔案(CLI 自己讀檔,或 API 成員呼叫 `read_file`)。附在提示詞裡的內容不算:審查時最多附上 6 個改動檔案的內容,附上的那幾個不必再讀也看得到。所以沒附上的檔案(`bug-beyond-inline-limit` 的第 8 個、`cross-file` 的呼叫端、`analysis-only` 的原始檔)判對卻沒讀檔,多半是猜對的。

模型輸出每次不同,**單次結果只是一個樣本**。比較兩個模型或兩個版本時,每題至少跑 10 次;兩邊共用本機 Ollama 時不要同時跑,會互相拖慢。

## 分享分數

歡迎把你用的模型的分數送 PR:跑 `npm run eval -- --runs 10 --save`,把 `eval/results/` 裡產生的那一個檔案送上來。

結果檔**只有數字**:日期、app 版本與 commit、審查者的 CLI 與模型、每題跑了幾次、判對幾次、失敗幾次、有讀檔幾次。不含任何審查內容、提示詞或本機路徑,所以可以放心分享。格式定義在 [score.ts](score.ts)。commit 後面帶 `-dirty` 代表跑的時候工作目錄有沒提交的改動,那份分數量的不完全是那個 commit;要分享的分數請在乾淨的 commit 上跑。
