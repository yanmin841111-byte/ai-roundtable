# 新增 CLI / API 選擇器文案

給 `#ext-picker` 用。Codex 尚未寫入預設用字時,以下「建議」欄即為應實作的字。卡片名稱仍讀範本 JSON 的 `label`,本表不要求改 `adapters/templates/`。

現況對照時點:renderer 仍是舊版(無分段、無搜尋、無空狀態、無卡片動作提示)。

| 位置 | 現況 / 規格預設 | 建議 | 理由 |
| --- | --- | --- | --- |
| 分段切換 | CLI / API / 全部 | **CLI**、**API**、**全部** | 與設定頁 `TYPE_LABEL`(CLI / API)一致;11 項只有這兩類主力,「全部」留給 Aider 這類 `js` 外掛 |
| 分段 `data-filter` | (尚未實作) | `cli`、`api`、`all` | 對應範本 `type`:`cli` / `openai` / 其他。預設選「全部」 |
| 搜尋框 placeholder | (尚未實作) | **搜尋名稱或說明** | 過濾範圍就是名稱與描述,不要寫成「搜尋 CLI」以免以為只搜指令 |
| 搜尋無結果 | (尚未實作) | **沒有符合的範本** | 短句即可;底下可加一行次要說明,見下方空狀態 |
| 空白範本分組標題 | 卡片叫「我的 CLI」「我的 API」,沒有分組標題 | 分組標題 **從空白開始**;卡片名稱維持 **我的 CLI** / **我的 API** | 「我的」單獨看會像已安裝的自訂項,但有分組標題後語意夠清楚;改 JSON 超出這次 renderer 範圍 |
| 品牌範本分組標題 | (無) | **現成範本** | 和空白組對仗;清單短時也保留,避免空白組看起來像被丟在頁尾 |
| 卡片動作提示 | 規格寫「複製範本 →」 | **使用此範本 →** | 點擊不是複製到剪貼簿,而是複製到擴充資料夾並打開編輯器;「複製」會誤導 |
| 說明文字(`index.html` 原 235 行) | 選一個範本複製到你的擴充資料夾,之後可以直接編輯。沒有你要的 CLI 或 API 時,選空白範本自己填。 | **點選範本即可複製到擴充資料夾並打開編輯器。** | 後句改由「從空白開始」分組承擔;前句與卡片提示重複,收成一行就夠 |

## 空狀態(建議整段)

搜尋或分段過濾後 0 筆時,取代卡片列表:

- 主句:**沒有符合的範本**
- 次句(有搜尋字時):**試試清空搜尋,或改選「全部」。**
- 次句(無搜尋、只是分段為空):**(不預期發生;若 JS 外掛被 CLI/API 濾掉,使用者應改選「全部」。可沿用同一句。)**

## 分組與排序(文案相關)

- 「現成範本」在上、「從空白開始」在下。空白是找不到現成項時的退路,不要置頂搶掉品牌卡。
- 空白組只收 `blank-cli.json` / `blank-api.json`(或 `id` 為 `my-cli` / `my-api`)。Aider 不是空白範本,放「現成範本」,且只在「全部」可見。

## 刻意不改

- 對話框標題維持 **新增 CLI / API**
- 範本 JSON 的 `label` / `description`(含「我的 CLI」「我的 API」)本輪不改,避免和 Codex 的 renderer 改動、Claude 的 diff review 打架
- 關閉按鈕 ✕、編輯器其餘文案不在此次範圍
